## 7. Menu SSR Feasibility (report only)

**Status:** approved  
**App entity:** BuilderReport `6ab6a27bd17ebdeeb79857a8`

### Before

/menu item names/descriptions are JavaScript-rendered; raw HTML has almost no menu content for Google to index.

### After

FEASIBILITY: Low. The app is a Vite + React SPA with no server-side rendering. Menu items are loaded via base44.entities.MenuItem.list() in the browser. Options: (A) Pre-render menu at build time — would require a build script that fetches MenuItem data and writes a static HTML snapshot; complex and goes stale as menu changes. (B) Add a static Menu JSON-LD block to index.html with hasMenuSection/hasMenuItem entries — Google can parse this for menu content without rendering JS; would need a sync workflow to keep it updated. (C) Switch to SSR/SSG framework (Next.js, Astro) — major architecture change, not feasible on Base44. RECOMMENDATION: Option B (JSON-LD menu schema) as a follow-up — add a backend function that generates the menu JSON-LD from MenuItem data and a workflow that syncs it into index.html on catalog changes. This is a follow-up task and does not block items 1-6.

## 6. Open Graph Tags (homepage)

**Status:** approved  
**App entity:** BuilderReport `6ab6a27bd17ebdeeb79857a7`

### Before

Homepage og:title said 'Tasty Threads — Flavor Isle Merch' with a merch image — the merch page's card was showing on the homepage.

### After

Root cause: keep-alive tab pages (Menu, Merch) all mounted simultaneously, and their Seo components ran on mount, overriding the homepage's OG tags. Fixed by adding an optional `path` prop to the Seo component — it now uses useLocation() and only applies meta tags when the current route matches. Home.jsx now has its own Seo with path='/' and correct OG tags (storefront image, diner description). Menu (path='/menu') and Merch (path='/merch') only apply their OG tags when visited directly. index.html OG tags also updated to match the diner (not merch).
